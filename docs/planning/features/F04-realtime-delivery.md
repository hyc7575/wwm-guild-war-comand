# F04 실시간 명령 전달

| 항목 | 내용 |
|---|---|
| 단계 | Phase 1 (MVP) |
| 우선순위 | Must |
| 관련 문서 | [도메인·프로토콜](../02-domain-and-protocol.md) §6~7, [F10 연결 관리](F10-connection.md) |

## 왜 필요한가

- 명령은 몇 초만 늦어도 쓸모가 없다. 전투 상황이 이미 바뀌기 때문이다.
- 방 안의 모든 사람이 같은 순서로 같은 상태를 봐야 한다. 순서가 엇갈리면 서로 다른 명령을 따른다.

## 아이디어

| 안 | 내용 | 판단 |
|---|---|---|
| WebSocket + 방마다 Durable Object 하나 | 방 하나가 상태와 연결을 모두 가진다. 순서를 보장하기 쉽다 | **채택 후보** |
| SSE + HTTP POST | 받기는 SSE, 보내기는 POST | 보류. 메인오더 쪽 왕복이 늘고, 방 상태를 한곳에 모으는 문제는 같다 |
| WebRTC 데이터 채널 (P2P) | 서버 비용 거의 없음 | 제외. 30명 메시 연결과 NAT 문제가 복잡하다 |
| 서버 없이 메인오더 브라우저가 중계 | — | 제외. 메인오더 회선과 브라우저에 모든 부하가 몰린다 |
| 상태 동기화 방식 | 이벤트 + 순번, 빠지면 스냅샷 | **채택**. 방 상태가 작아서 스냅샷이 싸다 |

## 전략

- **서버가 상태의 주인이다.** 메인오더는 "발행해 달라"고 요청하고, 서버가 ID와 순번을 붙여 전원에게 보낸다. 메인오더 화면도 서버가 보낸 이벤트로 갱신한다.
- **하나의 방은 하나의 실행 단위다.** Durable Object 하나가 방 하나를 맡으므로 동시성 문제가 생기지 않는다.
- **서버는 판단하지 않는다.** 서버는 형식, 권한, 빈도만 검사하고 중계한다. 명령 해석은 메인오더 브라우저가 한다.
- **잠들어도 상태를 잃지 않는다.** WebSocket Hibernation을 쓰면 메시지가 없을 때 메모리가 비워질 수 있다. 그래서 상태가 바뀔 때마다 Durable Object 저장소에 쓴다.

## 지연 예산

발화가 끝난 뒤 1초 안에 동맹원 화면에 보이는 것이 목표다.

| 구간 | 예산 [제안] |
|---|---|
| 발화 종료 감지 (무음 대기) | 500~700ms |
| STT 최종 결과 | 100~300ms |
| 명령 추출 | 5ms 이하 |
| 메인오더 → 서버 → 동맹원 | 200ms 이하 (p95) |
| 화면 그리기 | 50ms 이하 |
| **합계** | **약 1초** |

무음 대기 시간이 가장 크다. 너무 줄이면 문장 중간에 끊겨 오인식이 늘어난다. PoC에서 두 값을 함께 조정한다.

## 사용자 스토리

### US-F04-1 명령 즉시 수신
동맹원으로서, 메인오더 명령이 발행되면 바로 받고 싶다.

1. 발행 후 200ms(p95) 안에 내 화면에 도착한다.
2. 모든 동맹원은 같은 순서로 명령을 받는다.
3. 같은 명령을 두 번 받아도 화면에는 한 번만 반영된다.

### US-F04-2 발행 확인
메인오더로서, 명령이 서버에 전달됐는지 알고 싶다.

1. 서버가 받으면 메인오더 화면의 명령 옆에 확인 표시가 뜬다.
2. 2초 안에 확인이 오지 않으면 "전송 지연"을 보여 주고 다시 보낸다.
3. 거절되면 이유(권한, 빈도, 없는 파티)를 보여 준다.

### US-F04-3 비용 한도 보호
운영자로서, 무료 한도를 넘지 않게 하고 싶다.

1. 방당 접속 상한을 넘으면 새 접속을 거절한다.
2. 요청 빈도를 넘는 연결은 `RATE_LIMITED`를 받고, 계속 넘으면 연결을 끊는다.
3. 최대 유지 시간이 지난 방은 자동으로 닫힌다.

## 예외 상황

| 상황 | 처리 |
|---|---|
| 메인오더 연결이 끊긴 상태에서 명령이 추출됨 | 메인오더 브라우저가 대기열에 넣고, 재연결 뒤 보낸다. 10초 [제안]보다 오래된 명령은 보내지 않고 메인오더에게 알린다 (F10) |
| 서버 배포 중 연결 끊김 | 모든 클라이언트가 재접속하고 스냅샷으로 복원한다 |
| 악의적인 대량 접속 | 방 코드가 있어야 들어올 수 있다. 접속 상한과 빈도 제한으로 막는다. 필요하면 Cloudflare 기본 보호 기능을 쓴다 |
