# F09 명령어 사전

| 항목 | 내용 |
|---|---|
| 단계 | MVP: 기본 사전 + 파티 이름·별칭. Phase 2: 사전 편집기, 내보내기·가져오기 |
| 우선순위 | Should |
| 관련 문서 | [F03 명령 추출](F03-command-extraction.md), [F01 파티 구성](F01-room-and-party.md) |

## 왜 필요한가

- 동맹마다 부르는 말이 다르다. 어떤 동맹은 "들어가"가 공격이고, 어떤 동맹은 이동이다.
- 거점 이름, 작전 이름 같은 고유 용어는 기본 사전에 넣을 수 없다.
- 파서 정확도의 대부분은 사전의 품질에서 나온다.

## 아이디어

| 안 | 내용 | 판단 |
|---|---|---|
| 기본 사전 내장 | 행동·대상·위치·숫자·정정어 기본값을 JSON으로 배포 | **MVP** |
| 파티 이름·별칭 | 방 설정의 일부. 서버를 거쳐 공유 | **MVP** (F01) |
| 동맹 사전 편집기 | 표현 추가·삭제, 거점 등록 | Phase 2 |
| 사전 테스트 | 문장을 입력하면 해석 결과를 바로 보여 줌 | Phase 2. 편집기와 함께 |
| 내보내기·가져오기 | JSON 파일 또는 복사용 코드 | Phase 2. 서버 DB 없이 공동 지휘관과 나눠 쓰는 방법 |
| 서버 저장 동맹 사전 | 동맹 단위로 서버에 저장 | 제외. MVP는 영속 DB를 쓰지 않는다. 필요해지면 다시 본다 |
| STT 핫워드 연동 | 사전 단어를 STT 핫워드 목록으로 만든다 | PoC 결과가 좋으면 Phase 2 |

## 사전 구조

```ts
interface Dictionary {
  version: 1;
  name: string;                     // 예: "기본", "OO동맹"
  actions: Record<Action, string[]>; // 행동별 표현
  targetAll: string[];               // 전체를 뜻하는 말
  locations: { id: string; label: string; aliases: string[] }[];
  numberWords: Record<string, number>; // "일" → 1, "첫" → 1
  partySuffixes: string[];           // "파티", "팟"
  correctionMarkers: string[];       // "말고", "아니"
  cancelPhrases: string[];           // "방금 거 취소", "취소 취소"
}
```

- 기본 사전과 동맹 사전을 합쳐 쓴다. 같은 표현이 둘 다에 있으면 동맹 사전이 이긴다.
- 사전은 Zod 스키마로 검증한다. 가져오기에서 형식이 틀리면 거절하고 이유를 보여 준다.
- 저장 위치는 메인오더 브라우저의 IndexedDB다.

## 사용자 스토리

### US-F09-1 우리 동맹 표현 등록 (Phase 2)
메인오더로서, 우리 동맹이 쓰는 말을 사전에 넣고 싶다. 그래야 내 말투 그대로 인식된다.

1. "박아"를 공격 표현에 추가하면 바로 다음 발화부터 적용된다.
2. 이미 다른 행동에 있는 표현이면 경고하고, 어느 쪽에 둘지 고르게 한다.
3. 기본 사전의 표현을 끌 수 있다.

### US-F09-2 거점 등록 (Phase 2)
메인오더로서, 전장의 거점 이름을 등록하고 싶다.

1. "북문"을 위치로 등록하고 별칭 "위쪽 문"을 붙일 수 있다.
2. 동맹원 화면에는 등록한 이름("북문")이 보인다.

### US-F09-3 사전 공유 (Phase 2)
메인오더로서, 부지휘관과 같은 사전을 쓰고 싶다.

1. 내보내기를 누르면 JSON 파일이 저장된다.
2. 가져오기에서 형식이 틀리면 어느 부분이 틀렸는지 보여 준다.
3. 가져오기 전에 현재 사전을 덮어쓸지 합칠지 고른다.

## 열린 질문

- 거점 이름이 전장마다 다르면 사전을 전장별로 나눠야 하는가? 대상 전장 수를 확인한 뒤 결정한다.
