# F01 오더방 생성·참여 및 파티 구성

| 항목 | 내용 |
|---|---|
| 단계 | Phase 1 (MVP) |
| 우선순위 | Must |
| 관련 문서 | [도메인·프로토콜](../02-domain-and-protocol.md) §2, §4, §5 |

## 왜 필요한가

- 동맹전마다 회원가입 없이 바로 모여야 한다. 가입 절차가 하나라도 있으면 30명이 모이지 않는다.
- 동맹·전장마다 파티 수와 역할이 다르다. 전투 중에도 파티를 합치거나 나누는 일이 생긴다 (사용자 답변, 2026-11-26).

## 아이디어

| 안 | 내용 | 판단 |
|---|---|---|
| 방 코드 + 초대 링크 | 6자리 코드와 `/r/{코드}` 링크 | **채택**. 디스코드에 붙여 넣기 쉽다 |
| QR 코드 | PC 화면의 QR을 휴대폰으로 찍어 참여 | **채택**. 휴대폰을 보조 화면으로 쓰는 동맹원을 위한 것 |
| 고정 방 주소 | 동맹마다 매주 같은 주소 | 보류. 방이 끝나면 데이터를 지우는 원칙과 충돌한다. Phase 2에서 "지난 방 설정 재사용"으로 대신한다 |
| 지난 파티 구성 불러오기 | 메인오더 브라우저에 마지막 구성을 저장 | **채택**. 매주 같은 구성을 다시 입력하지 않게 한다 |
| 파티 구성 실시간 변경 | 운영 중 추가·삭제·이름 변경·순서 변경 | **채택** (사용자 요구) |

## 전략

- 참여 단계를 "링크 열기 → 파티 고르기" 두 단계로 끝낸다. 닉네임은 선택 사항이다.
- 파티는 안정적인 ID를 갖는다. 번호와 이름은 화면 표시용이다. 그래서 순서를 바꾸거나 이름을 고쳐도 동맹원의 선택과 진행 중인 명령이 유지된다.
- 파티 구성 변경은 "전체 교체" 메시지 하나(`parties.update`)로 보낸다. 서버는 버전을 확인하고 즉시 전원에게 알린다. 목표 반영 시간은 수 초 이내이고, 실제로는 F04의 전달 지연과 같다.

## 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-F01-1 | 메인오더는 파티 수(1~12)와 각 파티 이름(선택)을 정해 방을 만든다. 기본값은 5개 파티, 이름 없음이다 **[제안]** |
| FR-F01-2 | 방을 만들면 방 코드, 초대 링크, QR 코드를 보여 준다. 링크 복사는 한 번 클릭으로 한다 |
| FR-F01-3 | 메인오더 권한 토큰을 발급해 메인오더 브라우저에만 저장한다 |
| FR-F01-4 | 동맹원은 링크 또는 코드로 참여한다. 회원가입과 로그인은 없다 |
| FR-F01-5 | 동맹원은 참여 직후 파티를 고른다. "아직 모름"도 고를 수 있다 |
| FR-F01-6 | 동맹원은 언제든 파티를 바꿀 수 있다. 같은 방에 다시 들어오면 마지막 선택을 기억한다 |
| FR-F01-7 | 메인오더는 운영 중에 파티를 추가, 삭제, 이름 변경, 순서 변경할 수 있다 |
| FR-F01-8 | 파티 구성 변경은 모든 참가자 화면에 5초 안에 반영된다 |
| FR-F01-9 | 내 파티가 삭제되면 파티 선택 창을 다시 띄운다 |
| FR-F01-10 | 파티 별칭(예: "돌격대")을 정할 수 있다. 별칭은 명령 추출(F03)에 쓰인다 |
| FR-F01-11 | 메인오더 브라우저는 마지막 파티 구성을 저장하고, 다음 방을 만들 때 불러올 수 있다 |
| FR-F01-12 | 메인오더는 방을 종료할 수 있다. 종료 전에 확인을 한 번 받는다 |
| FR-F01-13 | 접속 현황(전체 인원, 파티별 인원)을 메인오더와 동맹원 모두에게 보여 준다 |

## 사용자 스토리

### US-F01-1 방 만들기
메인오더로서, 파티 구성을 정해 방을 만들고 싶다. 그래야 동맹전 시작 전에 동맹원을 모을 수 있다.

1. 방 만들기 화면에서 파티 수를 바꾸면 이름 입력 칸 수가 바로 바뀐다.
2. "만들기"를 누르면 2초 안에 방 코드, 링크, QR이 보인다.
3. 방 코드는 혼동 문자(0, O, 1, I, L)를 쓰지 않는다.
4. 지난번 구성이 있으면 "지난 구성 불러오기" 버튼이 보인다.
5. 같은 브라우저에서 탭을 닫았다가 다시 열어도 메인오더 권한이 유지된다.

### US-F01-2 방 참여하기
동맹원으로서, 디스코드에 올라온 링크를 눌러 바로 참여하고 싶다. 그래야 전투 전에 준비를 끝낼 수 있다.

1. 링크를 열면 파티 선택 화면이 바로 나온다.
2. 코드 입력은 대소문자를 구분하지 않는다.
3. 없는 방이거나 닫힌 방이면 "방을 찾을 수 없습니다"를 보여 주고 코드 입력 화면으로 보낸다.
4. 인원이 가득 차면 "방이 가득 찼습니다"를 보여 준다.
5. 휴대폰 세로 화면에서도 파티 버튼을 한 손으로 누를 수 있다 (버튼 높이 48px 이상).

### US-F01-3 파티 선택·변경
동맹원으로서, 내 파티를 고르고 필요하면 바꾸고 싶다. 그래야 내 명령만 크게 볼 수 있다.

1. 파티 버튼에는 번호, 이름, 현재 인원이 보인다.
2. 선택은 화면 상단의 "내 파티" 표시에서 언제든 바꿀 수 있다.
3. 새로고침해도 선택이 유지된다.
4. "아직 모름"을 고르면 모든 파티를 같은 크기로 보여 준다 (F06).

### US-F01-4 파티 구성 실시간 변경
메인오더로서, 전투 중에 파티를 합치거나 나누고 싶다. 그래야 실제 편성과 화면이 어긋나지 않는다.

1. 파티 편집 패널에서 추가, 삭제, 이름 변경, 순서 변경을 할 수 있다.
2. "적용"을 누르면 5초 안에 모든 동맹원 화면에 반영된다.
3. 이름이나 순서만 바뀐 경우 동맹원의 파티 선택은 유지된다.
4. 내 파티가 삭제된 동맹원에게는 파티 선택 창이 뜬다.
5. 삭제된 파티만 대상이던 명령은 취소 처리되고 이력에 "파티 삭제로 취소"라고 남는다.
6. 동맹원 화면에 "파티 구성이 바뀌었습니다" 알림이 3초 동안 보인다.

### US-F01-5 방 종료
메인오더로서, 동맹전이 끝나면 방을 닫고 싶다. 그래야 서버에 데이터가 남지 않는다.

1. "방 종료"는 확인 창을 한 번 거친다.
2. 종료하면 동맹원 화면에 "오더방이 종료되었습니다"가 보이고 더 이상 명령이 오지 않는다.
3. 종료 직전 세션 요약이 메인오더 브라우저에 저장된다 (F07).

## 예외 상황

| 상황 | 처리 |
|---|---|
| 메인오더가 같은 방을 두 탭에서 연다 | 나중에 연 탭이 권한을 가진다. 먼저 연 탭에는 "다른 탭에서 열렸습니다"를 보여 주고 음성인식을 멈춘다 |
| 메인오더 브라우저 저장소가 지워짐 | 권한을 되찾을 수 없다. 새 방을 만들어야 한다. MVP에서는 받아들이고, Phase 2에서 "메인오더 복구 코드"를 검토한다 |
| 두 변경이 동시에 들어옴 | 메인오더는 한 명이므로 드물다. `VERSION_CONFLICT`가 오면 최신 구성을 다시 받아 편집 화면을 갱신한다 |
| 파티 0개로 변경 시도 | 막는다. 최소 1개 |

## 열린 질문

- Q3. 동맹전 최대 인원과 일반적인 파티 수는? 기본값 5개와 접속 상한 60명을 확정하는 데 필요하다.
- 동맹원 닉네임이 필요한가? 메인오더가 "누가 어느 파티에 있는지"를 봐야 한다면 필요하다. MVP는 인원 수만 보여 준다.
