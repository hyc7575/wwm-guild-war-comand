# F07 명령 상태 관리

| 항목 | 내용 |
|---|---|
| 단계 | Phase 1 (MVP) |
| 우선순위 | Must |
| 관련 문서 | [도메인·프로토콜](../02-domain-and-protocol.md) §3 (규칙의 기준 문서) |

## 왜 필요한가

- 음성 명령은 계속 덮어쓰인다. "지금 유효한 명령이 무엇인가"를 정해 주지 않으면 화면에 명령 목록만 쌓인다.
- 잘못 발행된 명령을 취소했을 때 동맹원이 무엇을 해야 하는지가 분명해야 한다.
- 메인오더가 같은 말을 반복하는 것은 새 명령이 아니라 강조다.

## 아이디어

| 안 | 내용 | 판단 |
|---|---|---|
| 파티별 슬롯 스택 | 파티마다 명령 스택. 맨 위가 현재 명령 | **채택**. 취소하면 이전 명령으로 자연스럽게 돌아간다 |
| 단순 최신 명령 목록 | 가장 최근 명령만 유효 | 제외. 여러 파티 명령이 섞이면 파티별 현재 명령을 알 수 없다 |
| 자동 만료 | N분 뒤 명령을 지움 | 제외. 대기(HOLD)처럼 오래 유지되는 명령이 있다. 흐리게만 표시한다 |
| 취소 사유 자동 분류 | 발행 30초 안 취소는 "잘못 인식", 그 뒤는 "작전 변경" | **채택**. 메인오더에게 사유를 묻지 않고 KR3을 측정할 수 있다 |
| 세션 요약 | 방을 닫을 때 지표를 로컬에 저장 | **채택**. 서버 DB 없이 KR을 측정한다 |

## 전략

- 상태 규칙은 서버(Durable Object)에서만 적용한다. 클라이언트는 결과를 그린다.
- 규칙 코드는 서버와 테스트가 함께 쓰는 순수 함수로 만든다. `apply(state, event) → state`.
- 규칙의 세부 내용은 [도메인 문서 §3](../02-domain-and-protocol.md)이 기준이다. 이 문서와 다르면 도메인 문서를 따른다.

## 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-F07-1 | 발행된 명령을 대상 파티의 슬롯 스택에 올린다 |
| FR-F07-2 | 10초 안에 대상·행동·위치가 같은 명령이 오면 새로 만들지 않고 재강조 이벤트를 보낸다 |
| FR-F07-3 | 정정은 원래 명령의 자리를 이어받고, 원래 명령을 `CORRECTED`로 바꾼다 |
| FR-F07-4 | 취소하면 아래 명령으로 돌아간다. 아래 명령이 15분보다 오래됐으면 비운다 |
| FR-F07-5 | 파티 삭제 시 그 파티 슬롯을 지우고, 대상이 모두 사라진 명령은 `CANCELLED`로 바꾼다 |
| FR-F07-6 | 취소 사유는 메인오더가 고르지 않는다. 음성 명령을 발행 30초 안에 취소하면 `MISRECOGNIZED`, 그 외에는 `CHANGED`로 기록한다 |
| FR-F07-7 | 메인오더 화면에 파티별 현재 명령 목록과 각 명령의 취소 버튼을 보여 준다 |
| FR-F07-8 | 방을 닫을 때 메인오더 브라우저에 세션 요약을 저장한다 |
| FR-F07-9 | 세션 요약은 메인오더 화면에서 다시 볼 수 있고 JSON으로 내보낼 수 있다 |

## 세션 요약 항목

KR을 측정하기 위한 최소 항목만 모은다. 개인을 식별하는 정보는 넣지 않는다.

| 항목 | KR |
|---|---|
| 방 유지 시간, 음성인식 가동 시간 | KR1 |
| 음성인식 자동 복구 횟수 | KR1 |
| 최대 동시 접속 수, 파티별 최대 인원 | KR2 |
| 발행 수 (음성 / 수동), 후보 수, 후보 중 발행된 수 | KR3 |
| 취소 수 (잘못 인식 / 작전 변경), 정정 수 | KR3 |
| 발화 종료 → 서버 확인까지 지연 (중앙값, p95) | PoC 목표 |

```ts
interface SessionSummary {
  roomCode: string;
  startedAt: number;
  endedAt: number;
  sttActiveMs: number;
  sttRecoveries: number;
  peakMembers: number;
  peakByParty: Record<string, number>;   // 파티 번호 기준
  issued: { voice: number; manual: number };
  candidates: { shown: number; published: number };
  cancelled: { misrecognized: number; changed: number };
  corrected: number;
  latencyMs: { p50: number; p95: number };
}
```

## 사용자 스토리

### US-F07-1 현재 명령 유지
동맹원으로서, 지금 유효한 명령만 보고 싶다.

1. 새 명령이 오면 대상 파티의 현재 명령이 바뀐다.
2. 대상이 아닌 파티의 현재 명령은 그대로다.
3. 오래된 명령도 사라지지 않고 흐리게 남는다.

### US-F07-2 취소하면 이전으로
동맹원으로서, 잘못된 명령이 취소되면 원래 하던 일로 돌아가고 싶다.

1. 취소되면 화면이 이전 명령으로 돌아가고 "이전 명령으로 복귀"가 3초 동안 보인다.
2. 이전 명령이 15분보다 오래됐으면 "명령 없음"이 된다.
3. 이력에는 취소된 명령이 줄 그어져 남는다.

### US-F07-3 반복은 강조로
메인오더로서, 같은 명령을 다시 말하면 강조로 보이길 바란다.

1. 10초 안에 같은 명령을 다시 말하면 새 명령이 생기지 않는다.
2. 동맹원 화면에서 해당 카드가 재강조 움직임을 보인다.
3. 이력에는 한 건으로 남고 "반복 N회"가 표시된다.

### US-F07-4 세션 요약 확인
기획자로서, 동맹전이 끝난 뒤 서비스가 잘 동작했는지 숫자로 보고 싶다.

1. 방을 닫으면 메인오더 화면에 세션 요약이 보인다.
2. 지난 세션 요약 목록을 볼 수 있다 (최근 20개).
3. JSON 파일로 내보낼 수 있다.

## 예외 상황

| 상황 | 처리 |
|---|---|
| 이미 덮인 명령을 취소 | 스택 중간에서 빼기만 한다. 현재 명령은 바뀌지 않는다 |
| 이미 취소된 명령을 다시 취소 | 아무것도 하지 않고 `ack`만 보낸다 |
| 정정 대상 명령이 이미 덮였거나 취소됨 | 정정을 새 명령으로 발행한다. 메인오더 화면에 알린다 |
| 메인오더 브라우저가 방 종료 전에 꺼짐 | 세션 요약은 주기적으로(1분) 로컬에 임시 저장한다. 다음에 열면 마지막 임시 저장본을 보여 준다 |
