# Winds Command — 서비스 초기 기획서

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | Winds Command (가칭) |
| 상위 프로젝트 | WindsKit |
| 서비스 유형 | Local-first 기반 실시간 웹 서비스 |
| 대상 게임 | 연운 (Where Winds Meet) |
| 주요 사용자 | 동맹전 지휘관(메인오더) 및 참여 동맹원 |
| 운영 목표 | 비영리 무료 서비스, 월 서버 비용 0원 지향 |
| 지원 환경 | PC 및 모바일 웹 브라우저 |

## 2. 기획 배경

연운의 동맹전에서는 메인오더가 음성 채널을 통해 다수의 동맹원에게 실시간으로 전술을 전달한다.

그러나 전투에 집중하는 상황에서는 음성 명령을 놓치거나, 자신의 파티에 해당하는 명령을 구분하기 어려울 수 있다. 또한 여러 파티에 대한 복합적인 명령은 음성만으로 전달하기에 한계가 있다.

이를 보완하기 위해 메인오더의 음성을 실시간으로 인식하고, 전술 명령을 구조화하여 동맹원에게 시각적으로 전달하는 웹 서비스를 개발한다.

기존 디스코드 음성 소통을 대체하는 것이 아니라, 시각적인 정보 전달을 통해 보완하는 것을 목적으로 한다.

## 3. 서비스 목표

- 음성 기반 전술 명령의 시각화
- 파티별 명령 전달 및 정보 전달 누락 최소화
- 메인오더의 추가적인 조작 부담 최소화
- 별도 프로그램 설치 없는 웹 기반 서비스 제공
- 로컬 음성인식을 통한 서버 연산 비용 최소화
- 게임 클라이언트와 독립적인 서비스 구현

## 4. 핵심 서비스 흐름

### 메인오더

1. 웹사이트에 접속하여 오더방을 생성한다.
2. 초대 링크 또는 방 코드를 동맹원에게 공유한다.
3. 마이크 권한을 허용하고 음성인식을 시작한다.
4. 기존과 동일하게 디스코드에서 동맹전을 지휘한다.
5. 웹 서비스가 마이크 음성을 독립적으로 인식하고 전술 명령을 추출한다.
6. 추출된 명령을 오더방에 실시간으로 전달한다.
7. 동맹전 종료 후 오더방을 종료한다.

### 동맹원

1. 초대 링크 또는 방 코드를 통해 오더방에 접속한다.
2. 자신의 소속 파티를 선택한다.
3. 실시간 전술 명령을 화면에서 확인한다.
4. 자신의 파티에 해당하는 명령을 우선적으로 확인한다.
5. 필요시 이전 명령 및 전체 파티의 명령을 확인한다.

## 5. 핵심 기능

| 기능 | 설명 |
|---|---|
| 오더방 생성 및 참여 | 회원가입 없이 방 코드 또는 초대 링크로 참여 |
| 연속 음성인식 | 약 30분간 마이크를 활성화하고 실시간 음성 처리 |
| 전술 명령 추출 | 일반 발화와 전술 명령을 구분하고 대상·행동·위치를 구조화 |
| 실시간 명령 전달 | 동일한 방에 접속한 동맹원에게 명령 전송 |
| 전술 HUD | 텍스트, 아이콘, 색상, 애니메이션을 활용한 명령 시각화 |
| 파티별 명령 표시 | 소속 파티 및 전체 대상 명령 강조 |
| 명령 상태 관리 | 명령 유지, 변경, 취소 및 중복 처리 |
| 수동 명령 | 음성인식 실패 시 지휘관이 직접 명령 전달 |
| 명령어 사전 | 동맹별 전술 용어 및 표현 커스터마이징 |
| 연결 상태 관리 | 연결 끊김 감지, 재접속 및 현재 명령 복원 |

## 6. 전술 명령 처리

연속적인 음성을 모두 전달하지 않고, 유효한 전술 명령이 발생했을 때만 이벤트를 생성한다.

### 기본 명령 유형

- 집결 (GATHER)
- 이동 (MOVE)
- 공격 (ATTACK)
- 방어 (DEFEND)
- 후퇴 (RETREAT)
- 지원 (SUPPORT)
- 대기 (HOLD)

### 명령 구조

전술 명령은 다음 정보를 중심으로 구성한다.

- 대상: 전체, 특정 파티, 복수 파티
- 행동: 집결, 공격, 방어 등
- 위치: 중앙, 좌측, 우측, 특정 거점 등
- 상태: 신규, 변경, 취소
- 발행 시간 및 순서

### 처리 예시

| 메인오더 발화 | 처리 결과 |
|---|---|
| 1파티 2파티 중앙으로 모여 | 1·2파티 / 집결 / 중앙 |
| 3파티 오른쪽 지켜주세요 | 3파티 / 방어 / 우측 |
| 상대 인원이 생각보다 많네요 | 전술 이벤트 없음 |
| 전원 뒤로 빠져 | 전체 / 후퇴 |
| 중앙 말고 오른쪽으로 이동 | 기존 명령 정정 및 우측 이동 |

불확실하거나 해석이 모호한 명령은 임의로 확정하지 않는다. 필요시 원문 표시 또는 수동 명령으로 보완한다.

## 7. UI/UX 방향

### 메인오더 화면

- 오더방 및 초대 정보
- 현재 접속 인원
- 마이크 활성화 및 음성인식 상태
- 실시간 음성인식 자막
- 추출된 전술 명령 확인
- 수동 명령 및 명령 취소
- 음성인식 시작·종료

### 동맹원 화면

- 소속 파티 선택
- 현재 유효한 전술 명령
- 명령 대상 및 목적지 강조
- 전체 파티 명령 현황
- 최근 명령 이력
- 실시간 연결 상태
- 모바일 및 보조 모니터 대응

전투 중 짧은 시간 안에 명령을 파악할 수 있도록 가독성과 즉시성을 우선한다.

## 8. 기술 아키텍처

### 기본 처리 흐름

마이크 입력 → 오디오 처리 → 로컬 스트리밍 STT → 전술 명령 추출 → WebSocket 서버 → 동맹원 브라우저 → 전술 시각화

### Local-first 처리 원칙

- 음성인식 모델은 메인오더의 브라우저에서 실행한다.
- 음성 원본은 서버로 전송하거나 저장하지 않는다.
- 서버는 오더방 관리 및 전술 이벤트 중계만 담당한다.
- 사용자 설정과 명령어 사전은 로컬에 저장한다.
- MVP에서는 별도의 영속적인 서버 DB를 사용하지 않는다.

### 기술 스택 후보

| 영역 | 기술 후보 |
|---|---|
| Frontend | React, Vite, TypeScript |
| UI | Mantine, SCSS Modules |
| 상태 관리 | Zustand |
| 데이터 검증 | Zod |
| 마이크 수집 | MediaDevices API |
| 오디오 처리 | AudioWorklet |
| 음성인식 | sherpa-onnx, 한국어 Streaming Zipformer |
| 로컬 연산 | WebAssembly, Web Worker |
| 명령 분석 | 규칙 기반 Parser |
| 실시간 통신 | WebSocket |
| 서버 | Cloudflare Workers, Durable Objects |
| 시각화 | SVG, Canvas |
| 로컬 저장 | IndexedDB |
| 배포 | Cloudflare Pages |

기술 스택은 PoC 결과에 따라 최종 확정한다.

## 9. 운영 및 보안 원칙

- 무료 인프라 한도 내 운영을 목표로 한다.
- 회원가입 및 개인정보 수집을 최소화한다.
- 지휘관과 일반 참가자의 권한을 분리한다.
- 방 단위 접속 인원, 요청 빈도, 유지 시간을 제한한다.
- 종료된 오더방의 서버 데이터를 자동으로 정리한다.
- 게임 프로세스, 메모리, 패킷에 접근하지 않는다.
- 게임 조작 및 입력 자동화를 제공하지 않는다.
- 마이크 사용 여부를 명확하게 표시한다.
- 음성 원본을 저장하지 않는 것을 기본 정책으로 한다.
- 외부 보조 서비스 관련 게임 운영 정책을 확인한다.

## 10. 기술 검증 (PoC)

본격적인 서비스 개발에 앞서 핵심 기술의 실현 가능성을 검증한다.

| 검증 항목 | 초기 목표 |
|---|---|
| 연속 음성 처리 | 30분 이상 안정적으로 실행 |
| 한국어 음성인식 | 게임 용어 및 자연스러운 전술 명령 인식 |
| 처리 지연 | 발화 종료 후 1초 내외 명령 표시 |
| 명령 추출 정확도 | 95% 이상 목표 |
| 잘못된 명령 발행 | 1% 미만 목표 |
| 동시 접속 | 지휘관 및 동맹원 약 30명 이상 |
| 게임 성능 영향 | FPS 감소 5% 이내 목표 |
| 리소스 안정성 | 장시간 실행 시 메모리 누적 및 처리 지연 없음 |
| 마이크 호환성 | 디스코드와 브라우저 동시 사용 가능 |
| 백그라운드 실행 | 게임 플레이 중에도 지속적인 음성 처리 |

해당 수치는 초기 검증 목표이며, 실제 테스트 결과를 바탕으로 조정한다.

### Phase 0 — 기술 검증

- 브라우저 내 한국어 스트리밍 음성인식
- 30분 연속 음성 처리 및 성능 측정
- 전술 명령 데이터셋 구축
- 명령 추출 정확도 및 지연시간 검증

### Phase 1 — MVP

- 오더방 생성 및 참여
- 메인오더 음성인식

- 파티별 전술 HUD

- 회원가입 및 영구 계정 관리

- 유료 기능 및 수익화

## 13. 서비스 차별점

Winds Command는 기존 동맹 관리 서비스나 정적인 전술 설계 도구와 달리, 실제 전투 중 발생하는 음성 명령을 실시간으로 시각화하는 데 집중한다.

또한 로컬 음성인식과 경량 실시간 통신을 결합하여 운영 비용과 사용자 설치 부담을 최소화한다.

궁극적으로는 메인오더의 지휘 방식을 바꾸지 않으면서 동맹원에게 더 명확한 전술 정보를 전달하는 것을 목표로 한다.
